# 无来详解式

执行 [详解式规范](../../../guides/detailed-writing-style.md)。它与无来十段式并列；用户指定详解式时，不再强制十段、短段字数或三次公开反转。

## 工作方式

1. 先读作者完整原稿，明确核心判断、真实经历、读者和任务阶段。分析请求先给编辑意见，成文请求才写文章；指定标题保留。
2. 在后台厘清主要问题、必要概念、支撑理由、反例及成立条件。按 [无来观世法](../wulai-guanshi-fa/SKILL.md) 检查事实与推论，选有用的角度，不为框架添加无依据的内容。
3. 优先从准确概括的真实痛点开始，拆解机制，再展开解决之道；按[犀利、自信与逆向思维要求](../../../guides/writing-style.md#语言与语气)检验有用的反向追问，避免宏大鸡汤词。建立一条连续的解释路径。顺着读者理解问题所需的顺序推进：前段留下的问题由后段承接，先解释清楚再抬升判断。后台可列提纲，正文不显示提纲。
4. 正文只有标题、必要导读与自然段，无章节标题、段落编号、列表式正文或独立金句串。不把全文写成一个大段，不一句一行；用自然段承担不同的解释任务。
5. 中文正文默认3000–6000汉字（不含标题、导读和元数据），不限定段数；在此范围内按讲清所需的内容决定篇幅，作者明确另给要求时优先。不为压缩删除因果桥梁、有效案例或边界，也不以同义复述制造长度。
6. 通读时检查段间连接、概念一致性、论据是否支撑判断、反例是否真正回应、结论是否超出前文。情绪可以真实存在，不用理想状态否定人的感受；以具体生活或可理解的方向收束。

## 交稿

共用 [文章写作技能](../wulai-article-writing/SKILL.md) 的标题、导读、平台语言、图片和文件规则。正文结构以详解式为准；英文保留同等论证深度，以自然英语重新组织，不能自动压成十段短稿。制作笔记记录 `writing_mode: detailed`，分析阶段不自动创建英文版、图片或上线；成文、翻译与发布依当前任务授权执行。
